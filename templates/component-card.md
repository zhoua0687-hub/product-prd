# 组件规格卡

一个组件一张。七项的标签名不要改，脚本按标签检查。每一项怎么写见 `references/prd-standard.md`。

复制下面这一段，放到对应的节号下面。

```markdown
### 3.N.M 组件名

- **目的**：这个组件对用户或业务有什么用。
- **验收标准**：
  - 每条都能拿着原型当场判断对不对。
  - 写看得见的结果、具体的数字和条件。
- **交互状态**：

  | 状态 | 什么时候出现 | 界面表现 | 用户操作后 |
  |---|---|---|---|
  | 默认 | | | |

- **后台配置项**：

  | 配置项 | 类型 | 默认值 | 限制 | 说明 |
  |---|---|---|---|---|
  | | | | | |

- **文案**：

  | 位置 | 文案 | 备注 |
  |---|---|---|
  | | | |

- **数据字段和示例数据**：

  | 字段 | 示例值 |
  |---|---|
  | | |

- **异常和边界**：
  - 数据为空时：
  - 内容太长时：
  - 加载失败时：
```

## 填的时候

- 某一项确实没有内容，写「无」，不要删掉标签。
- 前端级把「数据字段和示例数据」的表换成四列：`字段名 | 类型 | 来源 | 示例值`。
- 使用者没说、你补的内容，行尾标 `〔建议〕`。
- 没定的地方写 `[待定 Q编号]` 加默认假设，并登记到附录 A。
- 提到别的组件、弹窗、页面，用 `【】` 括起来，名字和它的标题一字不差。

## 写完一张卡，自己过三问

1. 做原型的 AI 读完这张卡，还有哪里要猜？
2. 交互状态表里的每个状态，文案表里都有对应的文案吗？
3. 验收标准里提到「可配置」的地方，后台配置项里都有吗？
