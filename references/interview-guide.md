# 需求调研：各阶段问什么、怎么问

使用者脑子里有产品，但不一定按 PRD 的顺序想过。你的工作是把它一块一块问出来，同时不让他觉得在填表。

## 怎么问

- **一轮最多 4 个问题。** 多了他会挑着答，或者干脆说「你看着办」。
- **每个问题给 2～3 个选项。** 把你推荐的放第一个，说一句理由。人对着选项做决定，比对着空白快得多。
- **永远留两个出口：** 「你定」（他授权你按推荐做，写进 PRD 时标 `〔建议〕`）和「先不定」（写成 `[待定]`）。
- **先读材料再问。** 他给的文档、截图、聊天记录里已经有的，不要再问一遍，直接复述给他确认。
- **问具体的，不问抽象的。** 不问「你希望体验怎么样」，问「没登录的人点了参与按钮，是先弹登录，还是先让他看完再说」。
- **用他的词。** 他把抽奖码叫「抽奖码」，你就不要写成「凭证」。
- **听到解决方案，追一句问题。** 他说「加个跑马灯」，问一句「是想让人觉得很多人在参与吗」。目的清楚了，才能在组件卡里写出「目的」，也才好去查有没有更好的做法。

运行环境有结构化提问工具（能出选项卡片的那种）就用它；没有就在对话里列编号清单，让他回「1A 2C 3 你定」这样的短答。

## 阶段 0 · 启动

只问两个：

1. 这份 PRD 是给 AI 做**可点击的原型**，还是做**前端代码**？
2. 产品是 App、网站还是 H5？有几个端（比如用户端加运营后台）？

## 阶段 1 · 立项

先问目标市场，因为它会带出后面一串答案。

**目标市场**

- 主要给哪个国家或地区的人用？有没有第二梯队的市场？
- 界面用什么语言？只做一种，还是要多语言？
- 那边的人习惯用什么登录？用什么平台分享？
- 这类业务在当地有没有特别的规定（年龄、隐私、行业许可）？
- 用户主要用什么设备打开？

市场定了之后，你来带出建议（「这个市场一般用 X 登录、Y 分享，日期写成 Z」），他确认就行。

**项目背景**

- 现在这件事，用户或运营是怎么解决的？
- 现有的办法哪里最让人难受？
- 我们要做的东西，一句话是什么？

**产品定位**

- 如果只能用三个词形容这个产品，是哪三个？
- 有没有哪个产品是你觉得「就要那种感觉」的？是它的界面、流程，还是某个功能？
- 用的人分几类？各自来干什么？

**核心价值**

- 用户用了它，最明显的好处是什么？
- 这个好处靠产品里的什么东西实现？

**范围**

- 第一版必须有什么？没有它产品就不成立的那种。
- 哪些可以先做个简单版？
- 哪些明确先不做？

## 阶段 2 · 流程和状态

- 用户从哪进来（链接、搜索、别人分享）？
- 进来第一眼，他能做的最重要的一件事是什么？
- 做这件事之前，要不要登录、要不要满足什么条件？
- 做完之后，他看到什么？之后还会不会再回来？回来时看到的和第一次有什么不同？
- 这个产品自己有没有「阶段」（没开始、进行中、结束）？每个阶段页面有什么不同？
- 有没有需要等待的事（审核、开奖、发货）？等的时候用户看到什么？
- 最好的结局和最坏的结局各是什么？各自之后去哪？

每问出一个分支，就在流程图上加一条线，画完给他看图确认，比念文字快。

## 阶段 3 · 页面结构

- 一共有哪些页面？哪些是弹窗或浮层？
- 这一页，用户从上往下会看到什么？（让他像讲故事一样说一遍。）
- 这一块是为了让用户知道什么，还是让他做什么？
- 这一块在别的页面还会出现吗？
- 页面最底下是什么？有没有一直固定在屏幕上的东西（底部按钮、导航）？

边问边写大纲，然后生成思维导图给他看。他看着导图说「这里少了一块」，比你追问十句有效。

## 阶段 4 · 组件规格

每个组件按七项问，但不要机械地七个问题排下来。先自己根据前面的内容填出初稿，只问填不出来的。

| 项 | 填不出来时问什么 |
|---|---|
| 目的 | 去掉这一块，用户会少知道什么、少做什么？ |
| 验收标准 | 你看到原型时，怎么判断这一块做对了？ |
| 交互状态 | 没登录的人看到的和登录后有什么不同？活动结束后呢？点了之后呢？ |
| 后台配置项 | 这里面哪些内容是运营要经常换的？换的时候有没有限制（字数、图片比例）？ |
| 文案 | 按钮上写什么？成功和失败时各提示什么？ |
| 示例数据 | 能不能给我一组真实的例子（一个真实的奖品名、一个真实的赞助商）？ |
| 异常和边界 | 一条数据都没有时怎么办？文字特别长呢？网断了呢？ |

使用者想不到的边界，由你提出来。`references/component-patterns.md` 里每种组件都列了易漏点，照着问。

## 阶段 5 · 交付约束

- 原型或前端做在什么端？手机竖屏为主，还是也要适配电脑？
- （前端级）有没有指定的技术栈或平台？后台的配置是怎么传给前端的？
- 你会怎么验收？挑一条最典型的用户路径，从头到尾说一遍。

## 使用者答不上来时

- **不知道选哪个**：给他看同类产品是怎么选的（阶段动作里的「查」），再让他选。
- **说「都行」**：按推荐写，标 `〔建议〕`，在阶段确认时把这些建议集中念一遍。
- **说「以后再说」**：写 `[待定]`，补一句默认假设，告诉他「AI 会先按这个做」。
- **前后说法不一致**：把两处并排摆给他看，问以哪个为准，不要自己挑一个。
